01AI INFRA

AI 基础设施AI INFRASTRUCTURE

如果 AI 是一家明星餐厅，Infra 就是整座城市的电网、水管、道路和中央厨房。食客看不见它们，可没有它们，一道菜也做不出来。

它是什么

一层一层往上搭：最底下是电力和机房；往上是 GPU 芯片，真正“算”的地方；再往上是把几万张芯片连在一起的高速网络、存数据的仓库、分派任务的调度系统；最顶层才是你用到的 AI 服务。训练模型拼的是“蛮力”，回答问题拼的是“速度”。

从哪来

  1. 2006NVIDIA 推出 G80 显卡，第一款支持 CUDA 的 GPU，显卡开始做“通用计算”
  2. 2012AlexNet 在卧室里用两块游戏显卡训练完成，赢下 ImageNet 比赛，深度学习从此起飞
  3. 2025OpenAI、软银等宣布 Stargate 计划，目标到 2029 年投入 5000 亿美元
  4. 2026Dell'Oro 预测全球数据中心年度资本开支将首次超过 1 万亿美元

你见过的它

NVIDIA GPUGoogle TPUAWS / Azure / Google Cloud向量数据库Kubernetes 调度

五层发光的“地基”自下而上堆叠，数据像光点一样沿着柱子向上输送。

02HARNESS

马具 · 外壳AGENT HARNESS / EVAL HARNESS

模型像一匹力大无穷却不认路的野马。Harness 本义是“马具”，就是缰绳、马鞍和车架。套上之后，马力才变成能拉货、会转弯、不翻车的马车。

它是什么

Agent = Model + Harness

模型本身只会“接着往下写字”：记不住事，也动不了手。Harness 是模型之外的一切：调用工具（读文件、上网、跑代码）、管理记忆和上下文、设置权限与护栏、检查结果。同样的模型，配上更好的 harness，就是更能干的智能体。

Eval Harness 是另一个意思：统一的“驾考场地”，给所有模型出同样的题、用同样的标准打分。

从哪来

  1. 2021EleutherAI 发布 lm-evaluation-harness，后来成为 Hugging Face 开源模型排行榜的后端
  2. 2023–24研究界把模型外面这一层叫作 scaffolding（脚手架）
  3. 2026 初LangChain 的工程文章推广了 “Agent = Model + Harness”
  4. 2026.02“harness engineering” 一词流行，Mitchell Hashimoto 最早提到

你见过的它

Claude CodeCodex CLICursorClaude Agent SDKlm-evaluation-harness

中心发光的核心是模型；金色多面体笼子和环绕的轨道就是 harness，轨道上的小球是工具、记忆、护栏……

03AGENT LOOP

循环THE AGENT LOOP

就像厨师试菜：尝一口、加点盐、再尝一口，直到味道对了才上桌。智能体干活也是一圈一圈“试”出来的。

它是什么

语言模型一次只能“说一段话”：给它一段文字，它接着往下写。遇到要好几步才能做完的事（比如修一个程序错误），它自己动不了手，也看不到做完以后的结果。所以要在它外面套一个循环，一圈四步：

思考把任务和到目前为止的所有记录交给模型，让它想下一步该做什么。
行动模型说“我要用某个工具”，外面的程序真的去执行：读文件、搜网页、跑命令。
观察把执行结果原样交还给模型，让它看到真实情况，而不是靠猜。
验证对照目标检查：测试通过了吗？资料找全了吗？没达标就回到第一步再转一圈；达标了，模型不再要求用工具，循环就结束。

为什么要转圈

复杂的事很少一步做对。人也是这样：写完代码要运行，报错了再改。循环让模型每一步都能看到上一步的真实结果，错了当场纠正。代价是每转一圈都要花时间和钱，而且记录越积越长，长到装不下时，就得压缩或丢掉一部分。

刹车

循环必须有出口。常见的设置有：最多转多少圈、最多花多少钱或多长时间、什么情况算完成；删文件、付款这类关键操作，先问人一声。没有这些，模型可能反复做同一件没用的事。

粒子沿着光环一圈圈奔流；最亮的“彗星头”每经过一站，那一步就被点亮。红色方框是“刹车”。

从哪来

“根据结果不断调整”这个想法比 AI 老得多。家里的恒温器就是例子：测温度，太冷就加热，够了就停。

  2. 1966–72斯坦福研究院（SRI）的 Shakey 机器人，反复执行“感知、规划、行动”，是早期的智能体循环
  3. 2022.10Shunyu Yao 等人发表 ReAct 论文，让模型“边推理边行动”，两者交替进行
  4. 2023.03AutoGPT 开源，“AI 自己拆任务、自己一直干下去”引起广泛关注
  5. 2023.06OpenAI 在接口里加入函数调用，模型可以按固定格式“点名”要用哪个工具

一个具体例子：ReAct

ReAct 是 Reasoning（推理）加 Acting（行动）的缩写：让模型先写一句“我打算怎么做”，再发出动作，看到结果后接着写下一句。下面是示意，问题为自拟：

问《盗梦空间》的导演，第一部长片叫什么？
第 1 圈想：得先知道导演是谁。做：搜索。看：克里斯托弗·诺兰。
第 2 圈想：再查他的第一部长片。做：搜索。看：《追随》（Following）。
第 3 圈想：信息够了，不用再查。直接回答：《追随》。

Claude Code 和 Cursor

Claude Code你说“把登录页的错误修好”，它先读相关文件、搜索代码，再改文件、运行测试；测试报错，就按报错再改一轮，直到通过。官方文档把这个过程概括为收集信息、动手、检查结果，三件事交替进行。改文件、跑命令之前，会按你的权限设置先问你。
CursorAgent 模式也是这样：能搜索整个项目、修改多个文件、在终端里运行命令，再根据输出继续改。
Deep Research 类产品搜、读、发现缺了什么、再搜，最后才动笔写报告。

这几个产品的“骨架”基本一样。差别在外面那层 harness：给了哪些工具、权限怎么管、记录太长怎么压缩。

04GRAPH

图 · 网络COMPUTATION / KNOWLEDGE / AGENT GRAPH

Graph 就是一张地铁线路图：站点是“节点”，轨道是“连线”。在 AI 里，它有三种常见用法。

它是什么

这里的“图”不是图片，也不是柱状图，而是数学里的 graph：一堆点，加上点和点之间的连线。点叫节点，线叫边。边可以有方向（像单行道），也可以带名字或数字。顺着方向走，如果能绕回起点，这张图就“有环”。

很多事情说到底是“谁和谁有关系”或“先做什么、后做什么”。画成图，计算机就能沿着连线一步步推下去。AI 里最常见的三种图，回答三个不同的问题：

计算图先算什么，后算什么？
知识图谱谁和谁，是什么关系？
编排图干完这一步，下一步去哪？

从哪来

  1. 1736欧拉用“点和线”解决了哥尼斯堡七桥问题，这被看作图论的开端

绿色的网：每个亮点是节点，每条线是连线，光点沿线流动。继续往下看三种图。

一、计算图：让机器知道“怎么改”

训练神经网络时，先把整个计算拆成最小的步骤，每一步是一个节点。以最简单的“预测 = 输入 × 权重 + 偏置”为例：算出预测后，再和正确答案比一比，得到“损失”，表示错得有多远。

向前走一遍，得出预测和损失。再倒着走一遍，沿每条连线算出“这个参数稍微变大一点，损失会变大还是变小、变多少”，这叫梯度，这个做法叫反向传播。知道方向以后，每个参数往让损失变小的方向挪一小步。重复成千上万次，模型就学会了。参数多到上千亿个的大模型，原理也是如此。

来历

  1. 1970Seppo Linnainmaa 在硕士论文中提出反向模式自动微分，也就是“倒着走”的算法
  2. 1986Rumelhart、Hinton、Williams 在《自然》发表论文，说明反向传播能训练多层神经网络
  3. 2010Theano 把计算图和自动微分做成通用工具
  4. 2015.11TensorFlow 发布，先画好整张图，再运行（静态图）
  5. 2017.01PyTorch 公开发布，边运行边建图（动态图），写起来更像普通程序

你见过的它

PyTorch 的 loss.backward()TensorFlowJAX

左边的输入和参数汇入，向右算到“损失”（绿光）；粉色光点则从损失沿原路倒着传回参数。

二、知识图谱：把事实存成“关系”

把知识拆成“谁 —关系→ 谁”的小句子，叫三元组。比如：达·芬奇 —创作→ 蒙娜丽莎。很多条连起来就成了网，沿着网可以一步步追问：蒙娜丽莎收藏在哪？卢浮宫。卢浮宫在哪座城市？巴黎。

和大段文字相比，它的好处是事实清楚、能多步推出新答案、容易核对来源。缺点是建起来费人工，也装不下模糊的、没有固定说法的内容。

来历

  1. 2001蒂姆·伯纳斯-李等人在《科学美国人》发文提出“语义网”，设想让网页内容变成机器读得懂的关系
  2. 2007DBpedia 和 Freebase 出现：前者从维基百科抽取结构化数据，后者是大家共同编辑的开放知识库
  3. 2010Google 收购 Freebase 背后的公司 Metaweb
  4. 2012.05Google 发布知识图谱，口号是 “things, not strings”
  5. 2012.10维基数据（Wikidata）上线

和大模型结合：GraphRAG

大模型回答问题常靠“检索”：先找几段相关文字，再作答。但“这一大堆资料整体在讲什么”这类问题，几段文字回答不了。微软研究院 2024 年发表并开源了 GraphRAG：先让大模型读完全部资料，抽出人物、机构、事件和它们的关系，建成图；再把联系紧密的节点分成一群群，给每群写摘要；提问时用这些摘要来回答。

你见过的它

Google 搜索结果旁的信息卡WikidataGraphRAG

一条条写着“创作 / 收藏于 / 位于”的连线，把达·芬奇一路连到巴黎和米兰。

三、编排图：把 AI 干活的流程画出来

每个节点是一步：调用模型、调用工具、请人审核。连线决定下一步去哪，有的连线带条件：“模型要用工具，走这边；已经答完，走那边。”所有步骤共用一份“状态”，记着做到哪了、已经拿到什么。

和上一章那种“让模型自己决定下一步”的简单循环相比，图是让开发者提前规定好哪些路能走：更可控，也方便中途暂停，等人批准后接着跑。Anthropic 的文章把这两种做法区分为“工作流”（流程由代码事先定好）和“智能体”（流程由模型自己决定）。

来历

  1. 2014Airbnb 开发 Airflow，用“有向无环图”安排数据任务的先后，是早期的工作流图
  2. 2022.10LangChain 开源，主要把步骤串成一条直线（“链”）
  3. 2024.01LangGraph 发布，允许图里有“环”，这样才能画出循环

LangGraph 是开源的开发工具，自带保存进度、中途插入人工审核等功能。

要注意

并不是所有智能体产品都用图。Claude Code 这类编程助手，核心更像上一章那种由模型自己决定下一步的循环。图更适合步骤基本固定、需要分支和审批的业务流程，比如客服工单、报销审批。

你见过的它

LangGraphApache Airflow

“开始 → 模型 → 工具 → 模型”绕成一个回路，模型也可以转去人工审核，最后走到结束；光点沿箭头流动。
